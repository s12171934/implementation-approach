# 티켓 체크박스 커밋 리뷰 볼트 기록 규격

> [[티켓 체크박스 커밋 리뷰 루프]]가 남기는 기록 산출물의 규격이다. 어떤 노트를 몇 개, 어느 폴더에 쓰는지를 정한다.
> 「볼트」는 사용자의 노트 저장소(예: Obsidian 볼트)를 뜻한다. 볼트를 쓰는 환경이면 `vault-entry` 스킬로 볼트를 찾고 그 볼트의 작성 규칙을 따른다.
> **쓰는 주체는 산출물마다 다르다** (2026-09-15 개정) — 커밋 정리 노트는 **워커**가 자기 커밋 범위로 직접 쓰고, 기각 로그·브랜치 구현이력·PR 게시 목록·`_index` 는 **코디네이터**가 쓴다. 판정과 취합만 코디네이터에 남긴다 ([[코디네이터 호출 규율]]).

- **모든 문서는 그 코디네이터의 작업 폴더 `<프로젝트 폴더>/<이슈 키> <짧은 이름>/` 아래에 쓴다** — 예: `<프로젝트 폴더>/ABC-12 정렬 구현/`. 프로젝트 폴더의 위치는 그 볼트의 폴더 규칙을 따른다.
- **폴더는 배치 단위 하나당 하나, 곧 워크트리 코디네이터 하나당 하나다.** 여러 날에 걸쳐도 폴더는 그대로이고, 배치 단위가 체크박스면 그 체크박스를 이름에 넣는다.
- **최상위 코디네이터가 이 코디네이터를 띄웠으면 폴더도 그 안에 둔다** — `<프로젝트>/<최상위 코디네이터>/<이 코디네이터>/`. 최상위를 거치지 않았으면 프로젝트 폴더 바로 아래다.
- **최상위 코디네이터는 자기 폴더에 자기 것만 쓴다** — 티켓 순서·대응 확정, 트랙 수 결정, 프로젝트 단위 취합 목록. 커밋 정리와 기각 로그는 서브 폴더에 있고 위로 복제하지 않는다.
- **이름에 날짜를 넣지 않는다** — 시점은 프론트매터와 노트 내용이 가진다.
- 작업 폴더에는 인덱스 노트(볼트 관례가 `_index.md` 면 그것, `title`: `<이슈 키> <짧은 이름> 인덱스`)를 만들고 프로젝트 인덱스에 등록한다 — 체인이 한 칸 늘어난 만큼 인덱스도 한 칸 늘어난다.
- **커밋 정리 노트는 워커가 직접 쓰고, 그 노트의 절대경로와 부모 `_index` 등록 여부를 `worker_done` 에 실어 보낸다** — 이것이 유효한 보고 형식이다. 코디네이터가 워커의 보고 파일을 읽어 노트로 옮겨 적는 전사(轉寫)는 하지 않는다 ([[코디네이터 호출 규율]]).
- **코디네이터가 쓰는 노트의 재료만 워커의 보고 파일이다** — 기각 로그·브랜치 구현이력·PR 게시 목록. 그 파일에서 필요한 항목만 `grep -n`/`sed -n` 으로 꺼낸다.
- **커밋 정리 노트** — 커밋마다 하나. 티켓·체크박스·브랜치·커밋 해시, 무엇이 바뀌었는지, 라운드별 승인·기각 수, 참여한 리뷰 모델을 적는다.
- **모델별 토큰 사용량을 커밋 정리 노트에 함께 적는다** — 구현 모델, 리뷰 모델 각각, Opus 로 대체한 리뷰까지, 그리고 **그 코디네이터 자신의 몫**까지 모델 이름과 토큰량을 나눠 적는다.
- **코디네이터 몫을 빼면 기록이 아니라 과소보고다** — 3 차 전량 실측에서 비용의 **42.5%** 가 코디네이터 층이었다(2 차 스냅숏은 64.7%). 워커만 적은 노트는 체크박스 비용을 절반 가까이 적는 셈이다.
- **커밋 정리 노트를 워커가 쓰므로, 코디네이터는 리뷰어 몫과 자기 증분을 숫자만 워커에게 넘긴다** — 노트 하나에 필자는 하나다. 넘기는 것은 모델 이름과 토큰량뿐이라 메시지 크기가 문제되지 않는다.
- **코디네이터는 살아 있는 자기 세션을 스냅숏 차이로 잰다** — 커밋 정리 노트에는 직전 체크박스 스냅숏 이후의 **증분**을, 브랜치 구현이력에는 브랜치 전체 **누계**를 적고, 각 스냅숏의 누계값도 남겨 다음 증분의 기준이 되게 한다.
- **최상위 코디네이터의 몫은 최상위 자기 폴더에만 적는다** — 서브 폴더의 커밋 정리 노트로 내려 복제하지 않는다 (위 「자기 것만 쓴다」 조항).
- **토큰량은 세션 트랜스크립트에서 합산한다 — 세션을 닫아도 값은 남는다.** Claude Code 는 `~/.claude/projects/**/<세션 id>.jsonl`, Codex 는 `~/.codex/sessions/**/rollout-*.jsonl` 의 사용량 필드를 합산한다. 자기 세션 파일은 세션 id 로 고르고, id 를 잃었으면 그 작업 경로 디렉터리의 최신 수정 파일이 자기 것이다.
- **자기 세션 합산은 워커 합산과 같은 턴에 묶는다** — 측정이 턴을 늘리면 측정값 자체를 키운다 ([[코디네이터 호출 규율]]).
- 받지 못한 값은 추정해 적지 않고 무엇을 못 받았는지 적는다.
- **기각 로그** — 마지막 라운드 후에도 기각으로 남은 항목마다 리뷰 에이전트의 주장, 구현 에이전트의 기각 사유, 어느 라운드에서 나온 건인지를 적는다.
- **양측 표현을 그대로 옮긴다** — 한쪽이 상대의 주장을 고쳐 쓰지 않는 것이 이 로그의 값이다.
- **브랜치 구현이력** — **브랜치마다** 하나. 브랜치명, 커밋 목록과 체크박스 대응, 미해결 기각 건, 지라 상태, 구현·리뷰·코디네이터로 나눈 모델별 토큰 사용량 합계를 적는다.
- 티켓이 브랜치 하나로 끝나면 티켓 종료 시 하나이고, 여러 브랜치를 경유하면 브랜치를 닫을 때마다 하나다.
- **PR 리뷰 요청 게시 목록** — **티켓마다** 하나. 항목마다 티켓·브랜치·베이스 브랜치·커밋 범위·요청할 리뷰어와 미해결 기각 건을 적는다.
- 여러 브랜치를 경유한 티켓은 브랜치를 **스택 순서대로** 적는다 — 아래 브랜치가 먼저 리뷰되어야 위 브랜치의 diff 가 의미를 갖는다.
- 볼트에 쓸 때는 볼트 루트의 진입 문서(`AGENTS.md` 등)를 먼저 읽고 그 볼트의 노트 작성 규칙을 따른다.
- 같은 작업 폴더에 같은 주제의 노트가 이미 있으면 새로 만들지 않고 갱신한다.
- **볼트 문서를 그 코디네이터의 작업 폴더 밖에 쓰지 않는다** — 워커가 쓸 때도 같다. 폴더 경로는 코디네이터가 브리프에서 절대경로로 지정한다.
- **토큰 사용량을 받지 않은 채 에이전트를 종료하지 않는다** — 세션을 닫으면 받을 자리가 사라진다. 코디네이터 자신도 마찬가지다 — 마지막 누계는 **자기 종료 보고 직전**에 재고, 그 값이 브랜치 구현이력의 코디네이터 합계다.
