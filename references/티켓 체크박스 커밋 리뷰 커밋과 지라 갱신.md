# 티켓 체크박스 커밋 리뷰 커밋과 지라 갱신

> [[티켓 체크박스 커밋 리뷰 루프]]의 커밋 스코프와, 커밋 직후의 지라 체크·상태 전이 규칙이다.
> 커밋은 체크박스 하나와 정확히 같고, 푸시·PR·머지는 이 루프의 범위 밖이다.

- **커밋 스코프는 그 워크트리에 매칭된 티켓의 체크박스 하나와 동일하다.** 두 체크박스를 한 커밋에 넣지 않고, 한 체크박스를 두 커밋으로 쪼개지 않는다.
- **커밋은 구현 에이전트가 한다** — 브랜치와 작업 트리를 쥔 쪽이다.
- **리뷰 라운드가 끝나기 전에는 커밋하지 않는다.**
- 커밋 직후 그 체크박스를 지라 티켓에서 체크한다.
- **첫 커밋에서 티켓을 `진행 중` 으로 전이한다** — 출발 상태에 따라 전이 이름이 상태 이름과 다를 수 있다.
- **마지막 체크박스 커밋 후 `완료` 로 전이한다.** 조건도 입력 화면도 없는 전이이고 담당자 계정이면 API 로 그대로 실행된다 — 사람이 손으로 옮겨야 하는 단계가 아니다.
- **`완료` 전이는 `진행 중` 에서만 나타난다** — 첫 커밋에서 `진행 중` 으로 전이해 두었으므로 마지막 체크박스 시점에는 이미 가용하다.
- ⚑ **가용 전이를 미리 읽어 두고 판단하지 않는다** — 목록은 현재 상태에 따라 달라진다. 백로그 상태에서 읽으면 `완료` 가 보이지 않아 「종료 상태가 없다」는 잘못된 결론이 나온다 (2026-09-08 실제 사례).
- 상태 이름과 전이 규칙은 그 지라 프로젝트의 워크플로 설정이 정한다. 위 상태 이름은 예시이므로 실제 이름으로 읽는다.
- **PR 은 이 루프가 올리지 않는다** — 대신 올려야 할 PR 을 "PR 리뷰 요청 게시 목록"으로 정리한다.
- 그 목록은 종료 전이의 근거 문서다. 상태만 전이하고 요청 대상이 어디에도 없는 상태를 만들지 않는다.
- **푸시·머지도 이 루프의 범위 밖이다** — 사용자가 그 지시에서 직접 요청했을 때만 한다.

## 금지

- **리뷰 전 커밋** — 스테이지에 올린 채 리뷰를 받는 것이 이 루프의 전제다.
- **푸시·PR 생성·머지·브랜치 전환·형제 브랜치 위로의 리베이스.**
