# 구현 검증 결과 재사용

> 이미 통과한 검증을 다시 실행하지 않기 위한 기록·재사용·무효화 규칙이다.
> 검증 결과를 검증한 코드 상태와 묶어 남기는 것이 전제다. [[티켓 체크박스 커밋 리뷰 루프]]가 라운드마다 이 규칙을 쓴다.

- **검증 결과는 검증한 코드 상태와 묶어 기록한다.** 커밋 전에는 베이스 커밋과 스테이지 트리 식별자를 사용하고, 검증에 영향을 준 미스테이지·미추적 파일이 있으면 그 상태도 식별한다.
- **기록 항목** — 검증 범위, 실행 명령, 도구·의존성 버전과 관련 환경·설정, 입력·픽스처, 종료 코드, 결과 요약과 상세 로그 위치를 남긴다. 비밀 값은 기록하지 않는다.
- **동일 조건에서 성공한 검증은 재사용한다.** 라운드나 담당 에이전트가 바뀌었다는 이유만으로 같은 명령을 다시 실행하지 않는다.
- **재사용 전에는 유효성을 확인한다.** 코드·테스트·의존성·환경·설정·입력 중 검증 범위에 영향을 주는 변화가 없다는 근거를 남긴다.
- **변경된 부분과 영향 범위는 다시 검증한다.** 영향 범위를 확정할 수 없거나 외부 상태·시간·비결정성에 의존하는 검증은 재실행한다.
- **실패 재현과 수정 확인은 필요한 검증을 다시 실행한다.** 필수 최종 검증에 재실행 요건이 있으면 그 요건을 따른다.
- **실행 결과 재사용은 독립 리뷰를 대체하지 않는다.** 각 리뷰어는 현재 스테이지를 독립적으로 검토하며, 이전 리뷰어의 결론을 자기 판정으로 재사용하지 않는다.
- **대화에는 결과 요약과 식별자만 전달한다.** 상세 로그는 허용된 런타임 경로에 보관하고 실패·불일치 조사에 필요한 부분만 읽는다.
- **커밋 정리 노트에는 검증 출처를 남긴다.** 재사용한 검증 식별자와 유효성 근거, 새로 실행한 검증과 결과를 구분한다.
