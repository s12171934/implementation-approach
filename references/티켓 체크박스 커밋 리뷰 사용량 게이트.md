# 티켓 체크박스 커밋 리뷰 사용량 게이트

> [[티켓 체크박스 커밋 리뷰 루프]]의 두 게이트 — 구현 착수 전과 리뷰 라운드 시작 전의 모델 사용량 판정이다.
> 막혔을 때의 처리는 둘 다 같다: 리셋까지 기다린다.

- 게이트는 둘이며 **막히면 둘 다 기다린다.** 임계는 둘 다 **사용률 90%** 다.
- **판정 단위는 계정이 아니라 풀이다** — Claude 는 계정 2 개에 자동 전환이 켜져 있어, 활성 계정이 소진되면 fallback 으로 넘어가고 primary 리셋 후 자동 복귀한다 (계정 전환 도구의 설정을 따른다). 계정이 하나뿐이면 풀은 그 계정 하나다.
- 그래서 **활성 계정 하나가 90% 를 넘었다는 사실만으로 대기하지 않는다.** 대기는 **풀의 모든 계정이 막혔을 때**다.
- 전환은 실행 중인 세션을 끊지 않는다 — 다음 입력부터 새 계정이고, 전환 시점에 진행 중이던 응답 하나만 옛 계정을 쓴다.
- **모델 전용 한도는 계정 한도와 다르다** — 모델 한도만 걸린 계정은 폴백 후보에서 빠지지 않는다. 리뷰 게이트는 그 모델만 불가로 본다.
- **구현 착수 게이트** — 커밋 하나를 시작하기 전에 판정한다. 풀 전체가 막혔으면 착수하지 않고 리셋까지 기다린다.
- 구현은 건너뛸 수 있는 단계가 아니므로 다른 모델로 대체하지 않고 대기한다.
- 판정은 **커밋마다 다시 한다** — 앞 체크박스에서 통과했다는 것은 다음 체크박스의 근거가 아니다.
- 게이트에 걸리면 대기 사실과 리셋 예정 시각을 상위 코디네이터에 보고하고, 대기 중에는 그 워크트리에서 새 에이전트를 띄우지 않는다.
- **리뷰 게이트** — 라운드를 시작하기 전에 리뷰 모델별로 판정하고, **막힌 모델이 있으면 빼지 않고 리셋까지 기다린다.** 다른 모델로 대체하지도 않는다.
- 빼거나 대체하면 착수 때 정한 리뷰어 구성이 바뀌어 교차 신뢰도 신호가 사라진다 — 기다리는 비용이 그보다 작다는 판단을 두 프로젝트에서 유지했다.
- **게이트 판정은 라운드마다 다시 한다.**
- 대기와 계정 전환이 있었는지를 볼트 기록과 완료 보고에 남긴다.

## 사용량을 읽지 못할 때

- 사용량 조회 실패는 작업을 멈추는 사유가 아니다 — 조회 API 의 일시 오류(429 등)로 루프 전체가 서는 것을 막는다.
- **마지막으로 성공한 판독을 나이와 무관하게 다시 쓴다.** 그 판독의 리셋 시각이 이미 지났으면 0% 로 본다.
- 그 판독이 90% 이상이고 리셋 전이면 리셋까지 기다린다.
- **판독 이력이 한 번도 없으면 진행하고**, 판독 없이 진행했다는 사실을 기록한다.
- 조회 횟수를 줄인다 — 성공 판독은 짧게(수 분) 캐시하고, 실패 시 재시도는 한 번으로 그친다.
- 조회 경로 — Claude 는 `claude-usage-check` 스킬, GPT 계열은 Codex 세션 로그의 rate limit 스냅숏에서 창별 사용률의 최댓값으로 읽는다.

## 금지

- **사용량 90% 이상인 모델로 리뷰 강행.**
- **Claude 세션 사용량 90% 이상에서 구현 착수** — 초기화를 기다리지 않고 시작하지 않는다.
